EHR PRD v0.5 (곽두팔 · 2026-11-10 16:00 · 흐름 시험 23/23 · 근태 화면 v0.6 반영 · 근거: 11/5 피플엔컬처 미팅)

1. 문제

  • 사람을 ERP, Teams 라이선스, 인사 엑셀에 따로따로 등록합니다. 중심 데이터가 없습니다.
  • 인사 업무의 절반이 대사원 응대입니다. 기존 챗봇은 답만 해 주고 신청까지는 안 해 줘서 아무도 쓰지 않습니다.

    • 2. MVP 범위

    모듈핵심 기능데이터(SharePoint 목록)
    인원 명부등록·수정·퇴사 처리, 부서·직급·직무·입사일Employees(+Job 직무 한 줄)
    인사카드1인 1화면: 인적사항, 발령 이력, 연차 잔여Employees + Assignments
    근태종류는 4개만: 연차·오전반차·오후반차·외근(반반차·병가·경조·공가·출장은 2차). 신청 → 팀장 승인 → 인사 확정. 팀장 승인 때 「예약」, 인사 확정 때 「사용」으로 잡습니다. 반려 시 사유 필수, 반려 건은 「고쳐서 다시 신청」(원 건 번호를 이어 받아 새 신청), 승인 뒤 바꾸려면 「취소요청」 후 새로 신청(「변경신청」은 두지 않음, 취소 시 연차 복원). 신청번호는 LV-연도-4자리(예: LV-2026-0031). 저장 때 「잔여 − 신청 중 Days ≥ 이번 Days」를 확인해 넘으면 막습니다LeaveRequests(OriginalReqNo = 반려된 원 건 번호), ApprovalLog(모든 단계 이력) · 잔여 연차는 계산값(LeaveBalance 목록 없음)
    대화형 신청「11/12 오후 반차」라고 말하면 신청서 초안을 만들고 확인 버튼으로 제출LeaveRequests(상태=초안)
    대시보드오늘 부재자, 부서별 연차 사용률, 승인 대기위 목록 집계

    2-1. 연차 계산

  • 가용 잔여 = 발생 − 사용(인사 확정 Days) − 예약(상태가 팀장승인인 건의 Days만 · 취소요청 건은 사용으로 셈 · 스키마 v0.4와 같음)
  • 화면은 「잔여 · 예약 · 사용」 3칸으로 보여 줍니다(인사카드·근태 공통).

    • 3. MVP에서 뺄 것: 급여, 평가, 채용, ERP·Teams 자동 연동. 2차에서 영림원 주관사와 협의한 뒤 붙입니다.

    4. 결재선 (부서장 지정 방식: Departments 목록에 팀장·대결자 열)

  • 기본: 신청 → 팀장 → 인사 확정
  • 예외: 팀장 본인 신청은 본부장 → 인사 확정(ApprovalLog Step에 「본부장」 추가), 팀장 부재 시 대결자 승인(「대결」 표시), 사후·소급 신청은 3일 안에만 받고 인사가 증빙 확인
  • 본부장 대결자: Departments에 본부 행도 두고 대결자 열을 같이 씁니다. 비어 있으면 인사가 대신 승인합니다(가정 — 인사팀 확인 필요).

    • 5. 권한

  • 본인: 자기 카드와 근태만 봅니다. 본인 건은 본인이 승인할 수 없습니다.
  • 팀장: 자기 팀만 보고 승인합니다(화면 필터로 처리, 원본 목록은 인사만 접근).
  • 인사: 전체를 보고 수정합니다.
  • 목록 권한은 상속하지 않고 따로 둡니다. 주민번호·계좌는 MVP 열에서 뺍니다.
  • 개발 중에는 가짜 데이터 30명으로만 작업합니다.

    • 6. 완료 기준: 가짜 직원 A가 대화로 반차를 신청하면, 팀장 B가 승인하고, 팀장 승인 때 예약 +0.5, 인사가 확정하면 사용 +0.5 · 예약 0이 되고(잔여는 팀장 승인 때 줄고, 확정 때는 그대로), 대시보드 오늘 부재자에 A가 뜹니다. 이 한 바퀴가 돌면 1차 완료입니다.

    7. 결정 필요 (준보 님)

  • 배포: 인사 전용 비공개 사이트 (추천)
  • 결재선: 부서장 지정 방식 (추천, 직급 기준은 겸직·공석에서 깨짐)
  • 기존 그룹웨어(나온소프트) 근태 데이터 이관 여부
  • 본부장 대결자가 비었을 때 인사 대행으로 둘지
